# Lampa Uncensored для macOS

Нативная сборка byLampa Uncensored под macOS — universal (Apple Silicon + Intel), на актуальном
Chromium вместо Chromium 105 из windows-билда.

## Что откуда взялось

Исходник — `windows 32.zip` (byLampa, NW.js, сентябрь 2022). Из 291 МБ архива
приложением является только 8.6 МБ: `index.html`, `css`, `img`, `fonts`, `vender`,
`webos`, `plugins`. Остальное — рантайм Windows (`nw.dll`, `.exe`, `.pak`), он выброшен
и заменён на Electron.

Файлы `frame.html`, `loader.js`, `myObj.js` из windows-билда не перенесены: это
легаси-загрузчик, который `index.html` всё равно не использует, плюс NW.js-специфичная
рамка окна (`nw.Window`, `nwfaketop`). Их роль взял на себя `main.js`.

## Как обновляется

Два независимых контура:

1. **Контент Lampa — сам, при каждом запуске.** `app/index.html` тянет
   `lampainit.js`, `app.min.js` и `css/app.css` с `my.bylampa.online` с
   cache-buster'ом (новое значение каждые 15 минут), плюс плагины с
   `bylampa.github.io`. Пересобирать приложение ради новой версии Lampa не нужно —
   это то же поведение, что в windows-билде.
2. **Оболочка (Chromium/Electron) — через electron-updater,** меню
   «Lampa → Проверить обновления…». Канал настроен на GitHub Releases
   (`publish` в `package.json`). Пока релизов нет — проверка молча ничего не находит.

## Какой macOS поддерживается

Отчёт с iMac 2014: «не запускается, пишет что нужно не ниже 12–13 версии macOS,
а на нём 11-я». Это была не настройка, а сам бинарь: в `package.json` стояло
`minimumSystemVersion: 11.0`, но `Info.plist` самого Electron 45 требует 13.0.

Границы задаёт Chromium, а не мы:

| Electron | минимум macOS |
|---|---|
| 37 и ниже | **11 (Big Sur)** |
| 38–43 | 12 (Monterey) |
| 44 и выше | 13 (Ventura) |

Поэтому проект закреплён на **Electron 37.10.3** — последнем, который
запускается на macOS 11, и он же работает на всех новых. Одна сборка покрывает
и iMac 2014, и свежие маки. Проверено не по документации, а по бинарю:

```bash
/usr/libexec/PlistBuddy -c "Print :LSMinimumSystemVersion" \
  node_modules/electron/dist/Electron.app/Contents/Info.plist
# 11.0
```

Поднимать версию Electron можно только вместе с решением отказаться от
macOS 11 — и тогда честно менять `minimumSystemVersion`.

Чтобы это не сломалось молча во второй раз, порог проверяет сама сборка:
`scripts/after-pack.js` читает `minos` из `LC_BUILD_VERSION` у собранного
`Electron Framework` (у обеих срезов universal-бандла) и падает, если он не
`11.0`. Декларации в `Info.plist` недостаточно — она и соврала в первый раз.
Проверить руками у готового приложения:

```bash
otool -l "dist/mac-universal/Lampa Uncensored.app/Contents/Frameworks/\
Electron Framework.framework/Electron Framework" | grep minos
# minos 11.0
# minos 11.0
```

## Сборка и нумерация

```bash
npm install
npm run dist       # universal DMG + ZIP в dist/
npm start          # запуск без сборки
```

В macOS две разные версии, и обе нужны: `CFBundleShortVersionString` —
та, что видят люди (1.1.0), и `CFBundleVersion` — номер сборки, обязанный
расти с каждой выкладкой. `npm run dist` сам инкрементит второй
(`scripts/bump-build.js`) и кладёт оба в имя файла:
`Lampa-Uncensored-1.1.0-b1-universal.dmg`. Номер виден в «О программе».

Маркетинговую версию поднимать руками в `package.json` по смыслу изменений.

## Настройка прокрутки без пересборки

У слоя остался один параметр — скорость. Консоль (⌥⌘I):

```js
__macTune({ speed: 1.3 })
```

`1` — один к одному с трекпадом. Значение запоминается в `localStorage`.

Остальное настраивается в самой Lampa, её же средствами: **Настройки →
Интерфейс → Размер интерфейса** (`small` / `normal` / `bigger`). По умолчанию
`normal`; на окне ноутбука `small` показывает заметно больше. И **Настройки →
Управление → Тип навигации** — там видно, что стоит «Мышь».

## Подпись и установка на чужой мак

Сейчас приложение подписано **ad-hoc** (без Apple Developer ID). Это значит: запускается
везде, но при первом открытии macOS показывает предупреждение. На чужом маке:

```bash
xattr -dr com.apple.quarantine "/Applications/Lampa Uncensored.app"
```

Чтобы предупреждения не было вовсе, нужен платный Apple Developer Program ($99/год)
и сертификат **Developer ID Application**. Тогда:

1. В `package.json` → `build.mac`: убрать `"identity": null`, поставить
   `"hardenedRuntime": true`, добавить `"notarize": true`.
2. Экспортировать `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`.
3. `npm run dist` — electron-builder сам подпишет и отправит на нотаризацию.

Имеющийся в связке ключей сертификат **Apple Development** для этого не годится:
он работает только на машинах, зарегистрированных в вашем dev-аккаунте.

## Нативность под macOS

Что проверено по Apple HIG и что из этого следует.

**Рамка окна — системная.** HIG прямо запрещает рисовать свою:
«Avoid creating custom window UI… don't try to replicate the system-provided
appearance». В windows-сборке была своя полоса на 30 px с тремя кнопками —
она выброшена вместе с `frame.html`.

**Окно адаптируется.** HIG: «Make sure that your windows adapt fluidly to
different sizes» и «Choose a minimum and maximum size… If you don't set a
minimum, people could make it so small that UI elements overlap». Минимум —
1024×640, старт — 1280×800, размер, позиция и полноэкранный режим
запоминаются между запусками.

**Мышь и трекпад.** Здесь была главная ошибка первых версий, и стоит записать
её целиком, чтобы не повторить.

Считалось, что Lampa — чисто пультовый интерфейс и мышь не слушает вовсе.
Это неверно. В её коде есть полноценный режим мыши:

```js
elem.addEventListener('click', e => setTimeout(elem.trigger_click.bind(null, e), 20))

if (!Utils.isTouchDevice() && Storage.field('navigation_type') == 'mouse') {
  elem.addEventListener('mouseenter', elem.trigger_mouseenter)   // наведение → фокус
  elem.addEventListener('mouseleave', elem.trigger_mouseleave)
}
```

Включается он сам, если платформа опознана как десктоп:

```js
select('navigation_type', {...}, Platform.is('browser') || Platform.desktop() ? 'mouse' : ...)
function desktop() { return is('nw') || is('electron') }
```

А платформу Lampa определяет **по user-agent**:

```js
} else if (agent.indexOf("electron") > -1) { Storage.set('platform', 'electron') }
```

Первые версии подменяли user-agent на чистый Chrome — и этим своими руками
скрывали, что это Electron. `Platform.desktop()` становился `false`, Lampa
считала себя телевизором, включала пульт вместо мыши и свою экранную
клавиатуру. Поверх этого слой ввода повторял наведение и клики вручную,
и получалась двойная активация: срабатывал и её `trigger_click`, и наш
`Controller.enter()` — отсюда «кнопки не попадают по кликам».

**Правило: не подменять user-agent.** С родным агентом Lampa сама ставит
`navigation_type = 'mouse'`, `keyboard_type = 'integrate'` (системная
клавиатура вместо экранной), `Platform.macOS()` возвращает `true`. Проверено
запуском без единого слоя: наведение само ставит фокус.

**Прокрутка.** Единственное, что действительно надо чинить. Собственный
обработчик колеса у Lampa шаговый и загрублен по времени:

```js
if (Date.now() - scroll_time > 200 && inner) {              // один шаг в 200 мс
  Controller.enabled().controller[step > 0 ? 'right' : 'left']()   // прыжок фокуса
}
```

Он висит и на `wheel`, и на устаревшем `mousewheel` — перехватывать нужно оба,
иначе плавный слой работает одновременно с её прыжками.

Двигать пиксели своим `translate` поверх её `transform` можно (свойства
складываются), но это заводит два независимых состояния, и стрелки после
прокрутки расходятся с картинкой. Правильнее — её же документированный метод:

```js
/** Сдвинуть скролл на указанное количество пикселей без анимации */
this.shift = function (shift) {
  body.toggleClass('notransition', true)
  scroll_position = maxOffset(scroll_position - shift)   // своё состояние, свои границы
  translateScroll()
}
```

Экземпляр лежит на самом элементе (`html.Scroll = _self`), так что доступен как
`document.querySelector('.scroll').Scroll`. Ориентацию даёт `params().horizontal`;
ряд вложен в список, поэтому берётся первый по цепочке вверх, чья ориентация
совпадает с осью жеста. Знак проверен замером: `shift(+40)` сдвигает содержимое
вверх, то есть прокручивает вниз — как колесо с `deltaY > 0`. Границы Lampa
считает сама: тридцать `shift(-100)` подряд возвращают ровно в начало.

Обе оси проверены настоящими событиями колеса через `sendInputEvent`,
с замером позиции после каждого события:

```
--- 10 событий вперёд            --- 25 событий назад
  1:    -17   шаг -40              1:   -149   шаг 40
  2:    -57   шаг -40              2:   -109   шаг 40
  3:    -97   шаг -40              3:    -69   шаг 40
  4:   -137   шаг -40              4:    -29   шаг 40
  5:   -177   шаг -40              5:     11   шаг 40
  6:   -189   шаг -12   ← упор     6:     23   шаг 12   ← ровно в начало
  7:   -189   шаг   0              7:     23   шаг  0
```

Ровно пиксель в пиксель, упор в границу добирается остатком и дальше стоит,
возврат приходит точно в исходные `23`. Границы считает сама Lampa своим
`maxOffset` — мы их не трогаем. По вертикали то же: десять событий дают
`99 → -301`, по −40 на событие.

Два замера по пути соврали, и оба раза виноват был замер, а не код:

- мерился `.items-line__body` — он контейнер и всегда стоит на нуле,
  двигается `.scroll__body` внутри него;
- события слались каждые 50 мс, и Chromium их склеивал, отчего казалось,
  что назад прокрутка не доходит. На 90 мс всё сходится.

И одна особенность, на которую легко потратить час: у `sendInputEvent`
значения `deltaX`/`deltaY` идут по старому соглашению `wheelDelta`
(положительное — «от себя»), а в DOM приходит обратный знак. Так что
`deltaY: -40` в замере — это прокрутка ВНИЗ, а не вверх.

Диагностический слушатель `wheel` в фазе всплытия не видит ни одного события:
шим гасит их в фазе перехвата. Это и есть доказательство, что родной рваный
обработчик Lampa до колеса не доходит.

Итог: слой ввода — 95 строк вместо 292, и в нём нет ни наведения, ни кликов,
ни курсора, ни «назад». Всё это делает ядро.

**Шапка — нативный тулбар.** `.head` у Lampa — фиксированная полоса 58 px,
ровно высота маковского тулбара, поэтому кнопки окна ставятся внутрь неё
(`trafficLightPosition` 18×21), а содержимое шапки сдвигается вправо на 84 px,
чтобы «назад» не оказалось под ними. Сама полоса тянет окно
(`-webkit-app-region: drag`), её кнопки помечены `no-drag`.

**Типографика.** Lampa набрана `font-family: "SegoeUI"` — системным шрифтом
Windows. Это и читалось как чужое приложение раньше всего прочего. Слой
`shim/mac-style.js` переводит всё на SF Pro, подсветку фокуса — на системный
акцентный цвет (`systemPreferences.getAccentColor()`), скругления — на 12 px.
Css Lampa приходит с сервера уже после нас, поэтому `MutationObserver`
держит наш `<style>` последним в `<head>`.

**Один индикатор фокуса.** У Lampa своя подсветка карточки —
`.card.focus .card__img { box-shadow: 0 0 0 0.4em #fff }`, белое кольцо.
Если поверх неё положить ещё и заливку выделения, индикаторов получается два,
чего в macOS не бывает. Поэтому её кольцо переводится на системный акцент, а
заливка остаётся тем, у кого своего кольца нет: пунктам меню и кнопкам.

**Запуск.** Сервер `my.bylampa.online` не отдаёт ни `ETag`, ни `Cache-Control`,
поэтому Chromium перекачивает ~2 МБ скриптов при каждом старте. В `main.js`
стоит свой дисковый кеш (`session.protocol.handle('http')`): отдаёт с диска
сразу и обновляет в фоне.

Читать кеш обязательно асинхронно. С `readFileSync` на 2 МБ главный процесс
вставал ровно на то время, что кеш экономил, и выигрыш съедался целиком.
Замер на прогретой системе, фаза от запроса скриптов до «Prepare ready»:

| | фаза загрузки |
|---|---|
| из сети | 858 мс |
| с диска, синхронное чтение | 644 мс |
| с диска, асинхронное | **14 мс** |

Общее время до первого экрана этим не исчерпывается: холодный старт самого
Electron (пока его бинарь не в файловом кеше системы) занимает несколько
секунд и от нас не зависит.

Там же отсекается `fonts/SegoeUI/SegoeUI.ttf`: он битый (`OTS parsing error:
invalid sfntVersion`), не применяется никогда, а качается каждый запуск.

**Иконка.** macOS не маскирует `.icns` — форму задаём сами. Рисунок вписан
в сетку Apple: канва 1024, значок 824 по центру, поэтому в доке иконка стоит
вровень с системными. Пересобрать: `node scripts/inset-icon.js && ./scripts/build-icns.sh`.

## Что внутри main.js

- Ключи Chromium из NW.js-манифеста: `disable-web-security`,
  `disable-site-isolation-trials`, `disable-features=BlockInsecurePrivateNetworkRequests,
  AsyncDns,UseDnsHttpsSvcbAlpn`, `ignore-gpu-blocklist` — без них страница из `file://`
  не сможет грузить скрипты по `http://` и стучаться в локальную сеть (TorrServe).
- `User-Agent` НЕ подменяется. Раньше подменялся на чистый Chrome «чтобы Lampa
  не путалась» — и это было ровно наоборот. Lampa определяет платформу по агенту:
  `else if (agent.indexOf("electron") > -1) Storage.set('platform', 'electron')`.
  С чистым агентом `Platform.desktop()` становился `false`, Lampa считала себя
  телевизором и включала пульт вместо мыши. С родным агентом она сама ставит
  `navigation_type = 'mouse'` и `keyboard_type = 'integrate'`.
- `backgroundThrottling: false` — видео не затыкается, когда окно не в фокусе.
- Запоминает размер, позицию и полноэкранный режим между запусками.
- Внешние ссылки открываются в системном браузере, а не поверх приложения.
- Меню «Очистить кэш и перезагрузить» — сбрасывает закэшированный `app.js`
  из localStorage, если сервер отдал битую версию.
- Битый `SegoeUI.ttf` не качается вовсе: Chromium на него отвечал «OTS parsing
  error: invalid sfntVersion» при каждом запуске. Отдаём `404` с пустым телом.
  Сначала отдавали `204` — и конструктор `Response` его не принимал
  («Invalid response status code 204»: по стандарту у 204 тела быть не может даже
  пустого), так что обработчик падал с `TypeError` на каждом запуске. Нашлось
  только в логе настоящего собранного приложения, не в разработке.

## Почему «ничего не играет» и что с этим делать

Отчёт с iMac 2014: установилось, запустилось, но ни один ролик и ни одно кино
не пошло. Проверено на своём маке — часть этого воспроизводится везде и к
порту отношения не имеет.

**Каталог ≠ просмотр.** Каталог приходит из публичного TMDB, поэтому выглядит
живым даже когда смотреть нечего. Замер свежей установки:

    токен аккаунта: НЕТ
    плагинов: 1  (TMDB Proxy, его ставит сама byLampa)
    Lampa.Api.sources: tmdb          ← ни одного источника онлайн-просмотра
    online_choice: ""

Кнопка «Смотреть» в этом состоянии открывает не источники, а список ютубовских
трейлеров. Источники включаются в самом приложении: **Настройки → Плагины →
Онлайн**. Это настройка byLampa, а не сборки.

**Порт при этом исправен.** Все 48 запросов при старте отвечают `200`, включая
`lampainit.js`, `app.min.js` и все пять скриптов byLampa. Перехват `http` ничего
не ломает. Кодеки на месте: `MediaSource` + H.264 + AAC поддерживаются, HLS
через MSE играет (кадр 1280×720, время идёт), ютубовский трейлер играет в 1080p
— проверено скриншотом настоящего кадра, а не наличием элемента.

**Чем старый мак отличается.** Из NW.js-манифеста к нам переехал ключ
`ignore-gpu-blocklist`. Чёрный список Chromium — это перечень связок «железо
плюс драйвер», на которых видеопуть ломается; на Windows с живыми драйверами
ключ безобиден, а на iMac 2014 мы им принудительно включали ровно то, что
Google для этой машины выключил. Теперь ключ ставится только на macOS 12 и
новее, а на 11 Chromium решает сам.

**Если всё равно чёрный экран** — меню *Lampa Uncensored → Программное
декодирование видео*. Декодирует процессор: медленнее, но работает там, где
VideoToolbox на старой связке отдаёт пустой кадр. Выбор запоминается в
`prefs.json`, применяется с перезапуском. Проверено: с этими ключами тот же
трейлер играет.

## Что остаётся в логе и почему это нормально

При первом запуске после обновления с билда на Electron 45 в логе будет:

    IndexedDB backing store had unknown schema, treating it as failure to open.
    IndexedDB recovering from a corrupted (and deleted) database.

Это Chromium выбрасывает IndexedDB, записанную более новым Electron: схема
несовместима вниз. Данные пользователя это не затрагивает — Lampa держит всё
в `localStorage` (55 обращений в ядре против одного к `indexedDB`), а
`Local Storage/leveldb` переход 45 → 37 переживает целым: проверено на профиле,
созданном Electron 45 и дочитанном Electron 37 — тот же `000003.log`,
ключи (`keyboard_type`, `account_use`) на месте.

## Аккаунт

byLampa требует токен: QR-код в приложении → `@bylampa_sync_bot` в Telegram
или `sync.bylampa.online`. Настройки и токен лежат в
`~/Library/Application Support/Lampa` и переживают обновления.
